# 参考照片复刻：使用说明与实现范围

2026-09-12 · 首版功能

## 怎样使用

1. 打开页面顶部的“参考照片复刻”，上传一张 JPEG、PNG 或 WebP。支持 10 MB、2400 万像素以内的静态图片。
2. 选择“寻找原机位”或“在这里拍同款”。城市默认取当前表单，可以修改；不知道城市时可先留空，只分析画面，再采用模型提出的地点线索或手动补充城市。
3. 点击“分析画面并寻找机位”。Live 模式会调用已配置的多模态模型和真实信息 Provider；离线模式明确显示 Fixture 示例，不声称识别了上传图。
4. 查看画面理解、文件记录和最多三个候选。地图匹配只说明地标存在，不能证明它就是原照片的拍摄机位。候选照片来自现有安全图片代理，缺图时正常降级；来源链接在“来源与待核实信息”中。
5. 在下方原有表单设置起始日期、可拍时段与实际器材，再选比较 1、3 或 7 天。明确修改的摄影方向、主体、风格、光线和推荐偏好继续参与规划。
6. 选择一个候选，点击“确认候选，生成同款拍摄建议”。下方展示最多三个独立日期窗口、天气差异、站位/朝向、焦距、曝光起点和器材建议，不生成访问行程。

自动日期时段规则继续适用：今天从当前分钟起，未来自动日期从 00:00 起，默认到 23:59；人工时段和跨午夜设置保留。生成后主候选卡对应优先窗口，多日对照中显示其他选择。

## 实际完成的能力

- 多模态理解主体、画面风格、构图、相对光线、天气/季节观感、焦段倾向、长曝光/滤镜线索和最多三个地点假设。
- EXIF 白名单提取：相机、镜头、曝光、光圈、ISO、实际/等效焦距、原始时间文本和 GPS。缺少时区不擅自补齐。EXIF 标为文件记录，可能被修改，不能自动升级为已核实事实。
- 复用高德、联网搜索、社区发现、来源验证和参考图片 Provider。视觉摘要与用户补充一起传入发现；模型不能在结构化视觉结果中直接提供坐标或图片 URL。
- 用户确认后复用现有 LangGraph 和独立候选评估，不重新执行地点搜索；按天查询天气、计算太阳窗口，比较参考天气与未来预报的相似性。
- 参考等效焦距记录或视觉焦段倾向决定试拍目标，再受用户镜头范围约束。未知方向保留未知；长曝光与 CPL/ND 使用给条件式建议，不假装还原了原片设置。ND 换算提供明确测光前提的示例。
- 图片分析和生成均使用原有任务状态/SSE生命周期，已完成分析、预览和结果存入现有数据库。补充城市后会复用同张图的已有视觉分析，不重复付费识图。
- 修复历史列表超过 100 条后新结果不可见的问题：按创建时间取最近 100 条。已修改结果的原复刻对照会显示过期，避免多日说明与当前任务冲突。

## 主要代码

| 文件 | 作用 |
|---|---|
| `backend/app/reference_photos.py` | 图片解码、资源限制、EXIF 白名单、去元数据预览、数据库存储和删除 |
| `backend/app/vision.py` | 结构化多模态分析，45 秒超时，不开放搜索或执行工具 |
| `backend/app/reference_routes.py` | 上传、预览、分析、删除及安全候选图片接口；复用任务机制 |
| `backend/app/reverse_planning.py` | 参考意图、候选确认、跨日复用、焦距约束、条件对照和结果组装 |
| `backend/app/graph.py` | 接受服务端已核验候选与证据，沿用原图流程 |
| `backend/app/recommendations.py` | 参考天气相似性参与时窗选择与可解释降权 |
| `frontend/components/ReversePhotoPlanner.tsx` | 上传、分析、城市消歧、机位确认和删除 |
| `frontend/components/RecreationResult.tsx` | 参考图与多个拍摄窗口的对照展示 |

`TripBrief.reverse_context` 仅接受分析 ID、候选 ID 和 1～7 天范围；候选数据从服务端读取，不能通过提交任意坐标绕过核验。`ShotPlan.recreation` 保存来源、推断、文件记录和日期窗口；引用继续经过现有 Evidence 完整性校验。

## 接口

| 方法与路径 | 行为 |
|---|---|
| POST `/v1/reference-photos` | 请求体为图片二进制，Content-Type 为对应图片格式；返回 ID 与元数据摘要 |
| GET `/v1/reference-photos/{id}` | 读取图片记录 |
| GET `/v1/reference-photos/{id}/preview` | 去元数据的 JPEG 预览；禁止缓存 |
| POST `/v1/reference-photos/{id}/analysis` | `{brief, mode: original或similar}`；返回分析任务 ID，或地点澄清选项 |
| GET `/v1/reference-analyses/{id}` | 已保存的视觉分析、候选、来源和证据 |
| GET `/v1/reference-analyses/{id}/photos/{photo_id}` | 只代理该分析内已记录的真实图片，不接受任意 URL |
| POST `/v1/photo-research` | 原 Brief 加 `reverse_context: {analysis_id, spot_id, days}`，进入复刻规划 |
| GET `/v1/photo-research/{id}`、`/{id}/events` | 原有任务状态与 SSE 进度 |
| DELETE `/v1/reference-photos/{id}` | 删除上传预览及关联分析记录，取消相关运行任务 |

## 存储、隐私与失败处理

不保留原始上传文件，只保存校正方向、最长边 1600 像素的无元数据 JPEG，以及白名单 EXIF。模型收到预览，不收到独立 GPS 字段、文件路径或 API Key。图片/OCR 中的文字只是待分析内容，不获得执行权限。

删除会移除图片和分析，并阻止任务重新写回；已有拍摄结果仍保留生成时的派生说明、证据与文件记录，原图读取失败会正常降级。这不是数据库物理安全擦除或历史方案删除功能。

模型/地图服务失败时显示明确错误；已经保存的画面分析可继续查看。没有城市或没有可核验机位时，请补充地点再试，不补造精确坐标。服务重启后已完成分析及方案保留，进行中的任务不自动续跑。仍沿用本项目单用户、单进程、本地访问边界，不应直接暴露无认证 API 到公网。

## 验收

最终检查：166 项后端测试、18 项浏览器测试全部通过；TypeScript、Ruff、生产构建及已配置密钥扫描通过。

真实验收使用此前高德返回的一张公开颐和路参考照片。完成千问多模态理解、真实地图/来源核验、三个候选、确认其中一个、比较三天并返回三个窗口。确认后的规划没有再次搜索地点。最终 13 项检查通过，见 [真实报告](verification/reverse-photo-live.json)。

本轮没有测得通用定位准确率；一张照片通过不代表所有场景或所有社区可用。此次 Bilibili 直接元数据访问受限并降级，Wikimedia 不可用，Flickr 未配置，均不阻断高德和联网发现。

## 尚未实现或不能保证的部分

- 不具备全网以图搜图或原帖图片相似度检索索引；地点发现由视觉线索驱动现有文本搜索。模型假设与地图匹配不等于原机位身份确认，地点可信状态保持保守。
- 不保证厘米级站位、视线无遮挡、准确季节、滤镜档位或原片曝光。机位为区域级时必须现场找构图；缺少主体坐标时朝向为空。
- 多日适配度是可解释经验评分，没有实测校准。超出服务实际天气覆盖时保留天文草案和未知天气，不预测长期天气。
- 尚未做完整的景深求解交互、精准太阳入画方向求解、逐张候选参考图视觉比对和用户反馈校准；输入不足时不输出伪精确数值。
- 目前只支持单张静态图，不支持 RAW、HEIC、动画、视频或批量上传。历史方案和上传图片没有跨用户隔离；公网产品化仍需认证、配额和持久任务队列。

图片处理参考 [Pillow 官方 Image 文档](https://pillow.readthedocs.io/en/stable/reference/Image.html)，模型能力参考 [百炼官方视觉文档](https://www.alibabacloud.com/help/en/model-studio/vision-model/)。这两项为新依赖/能力依据，实际行为以上述项目测试为准。
