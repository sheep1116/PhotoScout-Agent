# PhotoScout：社区发现与候选机位升级说明

验收日期：2026-09-11。本文介绍本轮增量升级；保留 Next.js、FastAPI、LangGraph、SQLite 和现有图片、证据、审批机制。

## 1. 现在产品回答什么

PhotoScout 回答“当前有哪些值得拍的机位、为什么、什么时候、怎么拍”。每个地点独立比较可用时间，不再安排“先 A 后 B”。多个推荐窗口可以重叠，用户自行决定去哪几个以及访问顺序。

结果页默认是候选机位卡片。原来分散在拍摄安排、机位详情中的图片、站位、主体、方向、时间、天气、曝光起点、理由、注意事项、出行参考与来源合并展示。地图保留相机至主体方向，不显示串联机位的行程线。

没有可靠数据时明确写“未知”：停车、爬升、入口、步行耗时不会由模型补造。浏览器定位可用时计算起点至机位的直线距离，明确不是道路距离。步行预算、交通、门票偏好、客流和无台阶偏好不再默认排除候选。危险站位、已知关闭、开放冲突、雷暴、强风、强降水等门控仍然生效；开放未知的机位保持暂定。

## 2. 社区发现怎样接入

```text
PhotographyIntent + 目的地
  → CommunityService
      → BilibiliAdapter：匿名公开视频标题、简介、发布时间
      → IndexedAdapter：小红书、抖音的公开搜索索引入口
  → 公开 Web Search：提取带来源索引的摄影线索
  → 高德：核对相机地标、所属地点、被摄主体
  → SourceClaim / Evidence：把经验绑定到核验后的候选
  → 每个机位的天气、太阳几何、器材建议
  → 独立候选窗口与排名
```

社区标准记录 `CommunityPost` 保存平台、原始 URL、标题、简介、发布时间、获取方式及摄影词条。只从实际元数据中提取焦段、光线、时间和构图词；没有发布时间则为空，不推测。证据标记为 `REPORTED`，代表来源报告，不代表事实已核验。

只有原始 URL 已经关联该地图候选的社区记录，才加入该机位的经验 Claim。无关视频不能给机位增加建议。所有平台逻辑位于适配器，Planner 不接触登录、签名或网页解析。

### 已实现与暂未实现

| 来源 | 本轮接入范围 | 失败处理 |
|---|---|---|
| Bilibili | 匿名公共元数据搜索；对搜索索引实际发现的视频 URL 读取标题/简介 | 超时、HTTP 拒绝、业务风控、无效响应立即降级 |
| 小红书 | 统一适配器入口，使用公开 Web Search 命中记录 | 不保证命中，不获取登录内容 |
| 抖音 | 同上；保留后续扩展接口 | 不执行签名逆向或 CAPTCHA 绕过 |
| 高德 / Wikimedia / Flickr | 复用已有 POI 和图片 Provider | 图片不可用不阻断候选 |

Bilibili 每次直接搜索最多 3 条；索引回填最多 3 个视频。每次适配器操作总预算 6 秒，HTTP 超时 5 秒，不自动反复重试。搜索结果及失败状态缓存 30 分钟。元数据不可用时，两次付费搜索预算中的摄影发现请求扩大到通用公开来源，而非继续强制限定失效平台。`ENABLE_COMMUNITY=false` 可关闭直接社区访问，保留公开搜索。

这不是通用爬虫。没有引入账号池、Cookie 提取、代理轮换、验证码破解、视频下载、转录或批量评论抓取。公共元数据端点也不等于平台提供稳定的开发者 API；直接访问是否成功取决于当前网络和平台规则。

设计参考了 [MediaCrawler](https://github.com/NanmiCoder/MediaCrawler) 的平台模块隔离，以及 [Authurzk/mediacrawler](https://github.com/Authurzk/mediacrawler) 的统一接口与平台失败隔离。仅参考架构，没有复制代码或引入其爬虫依赖，也没有沿用登录、签名或绕过风控的实现。

## 3. 默认表单与时间处理

打开页面后，日期和时间使用浏览器本地日历、IANA 时区：开始时间向后取下一个半点/整点，结束时间为约 2.5 小时后。跨午夜时分别填写开始日期和结束日期；如果下一半点已经是次日，开始日期也随之切换。

先尝试浏览器定位，经高德逆地理编码得到城市；拒绝、超时或失败时尝试高德 IP 城市推测。定位只能填写默认值，用户一旦编辑目的地，迟到的定位响应不能覆盖输入。自动填写不会创建发现任务，也不会触发百炼搜索。

**IP 兜底当前识别服务器网络出口。** 本地运行时通常接近用户网络；代理或远程服务器部署可能得到其他城市，页面提示用户核对。没有信任客户端随意提供的转发 IP。浏览器坐标在前端取小数点后三位，用于城市查询；用户确认搜索后才随需求保存为距离计算起点。

后端保存带时区的时间，支持当日/次日窗口。夏令时跳时造成不存在的时间、回拨造成歧义的时间会明确拒绝，要求选择其他时间，不静默猜测。

“摄影器材”只保留画幅、镜头和三脚架。空镜头不再显示常驻“手机主摄”，而是提供未指定设备的通用起点；只有用户明确选择手机才使用手机建议。

## 4. 开发者阅读顺序

| 文件 | 本轮作用 |
|---|---|
| `backend/app/community/base.py` | 统一社区记录、适配器接口、原文摄影词条提取 |
| `backend/app/community/bilibili.py` | 公共搜索/详情读取、URL 白名单、访问失败处理 |
| `backend/app/community/indexed.py` | 其他社区的索引接入边界 |
| `backend/app/community/service.py` | 查询预算、缓存、独立降级、统一证据 |
| `backend/app/providers.py` | 搜索来源绑定、高德核验、社区经验与候选关联 |
| `backend/app/recommendations.py` | 每个机位独立门控、天气/太阳窗口比较、排序与出行信息 |
| `backend/app/graph.py` | 沿用原有单工作流，逐机位、逐日期获取条件 |
| `backend/app/location.py` | 浏览器坐标逆地理编码和 IP 城市兜底 |
| `backend/app/models.py` | 日期、起点、新候选字段和完整性检查 |
| `frontend/lib/defaults.ts` | 可测试的本地日期与半点默认值 |
| `frontend/app/page.tsx` | 定位竞争保护、器材表单、合并后的候选卡片 |
| `tests/test_candidates_community.py` | 社区至机位链路、降级、时间、门控边界测试 |
| `frontend/tests/defaults.spec.ts` | 定位优先级、跨天、不覆盖手动输入、不自动搜索 |

兼容性：API 和数据库仍沿用 `/plans`、`ShotPlan.tasks` 名称。新增 `presentation="candidates"` 表示独立候选；旧快照默认为 `itinerary`，旧版重叠校验不变。新结果每个机位最多一张卡片，窗口不可超出用户可用时间，路线必须为空。原 `engine.build_plan` 保留作历史兼容；新工作流统一调用 `build_recommendations`，没有为每种题材复制流程。

本轮还修复了原太阳计算的 UTC 日历错位：Astral 先按用户时区计算请求日期，再统一转 UTC，避免中国日出落到次日本地日历。候选采样加入精确的日出、黄金、蓝调边界，不再让半小时网格漏掉短暂蓝调；推荐窗口在相应光线结束时截断。天气刷新按各机位和实际日期计算。

## 5. 验收结果与重跑

- 后端：140 项测试通过，包括真实适配器契约到地图候选的完整模拟链路。
- 页面：12 项 Playwright E2E 通过（11 项离线 + 1 项保存的真实结果），覆盖桌面、390px 手机、证据、审批/撤销、图片降级和默认值。
- TypeScript 检查、生产构建、Ruff 通过；63 条既有离线规则评测通过。离线评测不等于真实来源准确率。
- 真实验收：2026-09-11，南京玄武湖，次日 14:00–19:00，风光/建筑意图。最终 18 项检查全部通过；耗时约 25 秒，2 次搜索，13 次 Provider 调用，返回 1 个可地图匹配的“荷花栈道”候选、紫峰大厦主体方向、逐时天气及 3 张通过代理加载的高德实图。

实际调试经历了三次显式 Live 生成：最初平台限定搜索失败；扩大第二路搜索后只有区域候选；最终改为社区不可用时扩大主发现搜索后通过。没有把失败结果替换成 Fixture，也没有靠放松地理/来源核验获得通过。记录的 token 数不是费用，金额以账户账单为准。

[最终机器验收报告](verification/candidate-discovery-live.json) 与 [真实完整结果](verification/candidate-discovery-plan.json) 保留可复查证据。使用已有结果重跑不会创建新的付费发现：

### 必须保留的限制

本机 Bilibili 直接访问受限，成功元数据路径只通过模拟契约测试；真实验收证明的是其失败不会阻断公开搜索、高德和候选生成，不能称为 Bilibili 真实内容获取成功。小红书、抖音仍是索引入口。Wikimedia 本次不可用，Flickr 未配置。

候选数量不保证：这一真实请求只有一个保留机位，其他线索因地点范围、歧义或证据不足跳过。`mapped_viewpoint` 不是实测站位，方向不保证无遮挡；原文经验没有逐句人工核验，开放仍未知。社区焦段仅作可追溯经验展示，曝光起点由确定性规则生成，不直接照抄帖子。距离、停车等信息不完整，也尚未实现多种交通方式路线比较。

当前仍是本地单用户工作台，没有在本轮发布公网或增加多租户认证、计费、账号授权和运营队列。
