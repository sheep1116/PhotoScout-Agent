## 本轮发现并修复的问题

### 1. 来源被流式帧重复计数

百炼真实 SSE 会在多个帧中重复返回同一 `search_info`。初版探针把 7 个来源累加为 581 项。现按引用索引及 URL 去重；仍保留响应大小上限，调整为适应重复元数据的 2,000,000 字符。

### 2. Token 用量没有跨请求累加

原实现取所有帧用量的最大值，会低估多次搜索总量。现在每条流取该请求累计用量，再把各请求相加；缓存命中不增加本次请求 tokens。增加 `search_calls` 和 `search_cache_hits`，避免把缓存生成误称为零成本的全新搜索。

### 3. 常用地点名无法匹配高德正式名称

真实搜索中常出现“鱼嘴湿地公园”“先锋书店（五台山店）”等名称，高德可能返回带城市前缀、不同括号或“总店”的名称。新增有限规范化：城市前缀、全半角、空白、总店及常见区域后缀。只采用唯一匹配；不同分区、同名多条和无关唯一结果仍拒绝，不以首条结果凑数。

### 4. 高德业务失败难诊断，连续 POI 请求缺少节流

HTTP 200 不代表高德业务一定成功。增加 `infocode` 数字错误码映射；对限流/忙碌码有限退避重试，默认请求间隔 0.6 秒。可用 `AMAP_MIN_INTERVAL` 调整。日志与错误信息不带密钥，也不回显上游自由文本。失败阶段增加诊断事件。

初次排错观测到了 POI 业务失败，旧版未保留具体 infocode，因此不追溯断言所有失败均由某一个限流码导致。修复后的限流分支通过模拟回归验证。

### 5. “有引用”不足以保证引用支撑具体地点

初次搜索把通用摄影教程绑定到南京机位，链路形式完整但内容依据不足。现将结构化输出约束放入 system 消息，将目的地查询放入独立 user 消息，并使用搜索意图参数。增加保守的标题地域/地点相关性检查；无关引用不用于候选，缺乏依据的候选被排除。缓存键升级为 v2，避免继续复用旧搜索意图的结果。

这项检查是元数据相关性筛选，不是自动逐句原文核验。它允许漏掉标题没有地名的好资料，也不保证所有相关标题下的陈述都正确。

### 6. 来源页面显示未被采用的搜索结果

生成结束只保留被证据实际引用的来源。最终网页来源数包含天气、天文和规则记录，**不等于独立网页数**；本次独立采用网页为 3 个。

## 调用与费用

本轮调试和验收共主动触发 **6 次百炼搜索请求**：初始探针 1 次、初次网页尝试 2 次、搜索意图修复探针 1 次、修复后冷缓存网页生成 2 次。其余同需求复验使用搜索缓存。探针和排错还调用了地图及天气接口。

9,050 tokens 是修复后冷缓存计划的两次搜索合计，**不是整个调试过程的累计用量**。旧版中间请求没有保留完整可累加用量，不拼造总 tokens。未读取账户账单，人民币成本不估算为 0；实际费用以服务账户账单为准。

`.env` 未修改，API Key 未写入前端、报告或测试结果。探针和验收脚本对输出/结果检查已配置密钥，失败时不输出带鉴权请求的异常详情。
