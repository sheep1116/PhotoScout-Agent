# Agent 优先发现与地图增强

日期：2026-09-12。本轮把 PhotoScout 从“核验通过才展示”改为“Agent 先回答，PhotoScout 再增强”。

## 用户体验

用户只需描述想拍的画面。确认页保留原文，并补齐已确认目的地、日期、当地时间、题材、主体、风格、光线、偏好，以及画幅、镜头和三脚架信息。所有这些字段会作为一个完整摄影任务发送给千问联网 Agent；未填写的条件仍标记为未知，不伪装成用户要求。

结果页首先展示千问的完整建议、候选站位、朝向、构图、时间判断、器材适配、参数起点和引用链接。随后展示 PhotoScout 的地图与环境增强结果。两层结果独立保存：地图无法定位、引用标题过于笼统或主体坐标缺失时，Agent 建议不会消失，只降低核验状态。

## 数据流

`用户描述 → 可编辑 TripBrief → 完整 AgentBrief → 千问 answer_summary/candidates/source_indices → AgentAnswer → 高德地点解析 → PhotoSpot → 天气/太阳/器材/空间几何 → ShotPlan`

- `AgentCandidate` 是发现线索，可以没有坐标；状态为 mapped、area、map_only、unlocated 或 rejected。
- `PhotoSpot` 继续要求有来源的 WGS84 位置，不接收模型坐标，也不为无法定位的建议制造地图点。
- `ShotPlan.agent_answer` 保存完整 Agent 层；旧计划读取时自动得到空 AgentAnswer，保持兼容。
- 搜索来源只保留 Agent 明确引用的链接或实际证据使用的链接；未引用的搜索噪声不进入计划。

## 核验语义

| 状态 | 含义 |
|---|---|
| mapped | 高德地点已匹配，且引用标题能关联地点；仍不证明精确站位、开放或无遮挡 |
| area | 只能定位到所属区域，不能把区域中心说成相机位置 |
| map_only | 高德可定位，但引用标题不足以证明该机位 |
| unlocated | Agent 建议与链接保留，暂不绘制地图点 |
| rejected | 与用户已确认的景区或行政范围冲突，保留原始建议并解释不采用原因 |

天气、开放、安全和光线不由 Agent 文本直接授信。PhotoScout 继续使用天气服务、Astral、来源类型和确定性规则。参数只作为曝光起点；用户器材会进入 AgentBrief，也会进入本地器材规则。

## 拍摄方向与同框判断

当相机点和多个主体都能通过高德独立定位时，后端分别计算每个主体的方位角、包含全部主体的最小方位跨度，以及当前推荐等效焦段的近似水平视角。结果页显示每个主体的方向和“平面几何上可能同框 / 建议缩短焦段或调整站位”的判断；地图用相机到各主体的带箭头关系线表达朝向。

这个判断不证明实际视线无遮挡，也不包含楼体高度、地形和三维遮挡。前端与证据说明继续明确这一边界。

## 失败降级

- 有 Agent 回答但没有地图候选：任务仍成功保存，展示回答、链接和 unlocated 状态；太阳、天气与方向显示为无法按机位计算。
- 有地图点但来源标题不足：生成 map_only 地图候选，不把链接当作已证实机位。
- Agent 和搜索都没有返回可用内容：才以 `NO_AGENT_RESULTS` 结束。
- 高德、图片或天气的单项失败不会删除已保存的 Agent 层。

## 验收覆盖

自动测试覆盖完整时间与器材进入 Agent 请求、无引用回答仍能返回、标题相关性失败不再删除地图候选、无法定位的 Agent 回答可形成有效计划、双主体方位与同框判断、旧计划兼容、前端 Agent 面板与现有保存/提案流程。
